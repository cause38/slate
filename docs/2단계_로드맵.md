# Slate 2단계 로드맵

> 1단계(W1~W8) 완성 후 계획. PRD "2단계" 항목 + 미정사항 + 1단계 후속 태스크 + 개발 중 발견한 기술부채를 취합.
>
> **정렬 기준 (확정)**: *팀이 실제로 쓸 수 있게 만드는 것*을 최우선에 둔다. 1단계는 코드가 완성됐지만 로컬 호스팅이라 접근자가 1명이고, GitHub·Slack·Jira는 모의·드라이런으로만 검증된 상태 — 즉 **"완성"과 "가동" 사이가 비어 있다**. 그 간극을 Wave 1에서 메우고, 도구의 존재 이유인 지라 이탈을 Wave 2에서 실행한다. 편의 기능과 고도화는 실사용 피드백을 받은 뒤로 미룬다.
>
> 표기: 규모 S(1~2일)/M(3~5일)/L(1주+). 의존성은 선행 항목 표시.

| 항목 | 규모 | 의존성 | 메모 |

**완료 기준**: 활성 이슈·에픽이 Slate에 있고, 지라는 읽기 전용으로 물러난다.

## 유지되는 원칙

1단계에서 확정한 비협상 항목은 2단계에서도 유지한다. 변경이 필요하면 문서에 명시적으로 남기고 진행.

- 이슈 키는 자연 증가·0 패딩 없음 (`DOTOLI-42`)
- 모든 테이블 RLS 활성화, `service_role`은 서버·Edge Function 전용
- 다중 프로젝트가 데이터 모델 전제 (DOTOLI 하드코딩 금지)
- 슬랙은 워크스페이스 단위 단일 통합 채널, **변경 1건 = 메시지 1개** — 스레딩 도입 시에만 재합의
