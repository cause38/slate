# Slate — 디자인 핸드오프

> 와이어프레임을 실제 디자인으로 옮기기 위한 입력 문서. 클로드/디자이너 누구에게 주든 그대로 사용 가능.

| 항목 | 내용 |
|---|---|
| 도구 이름 | **Slate** (사내 이슈 트래커, 지라 대체) |
| 함께 줄 파일 | `Slate_와이어프레임.html`, `PRD_사내_이슈트래커.md` (선택: `TDD_Slate_기술설계서.md`) |
| 클로드에게 줄 때 | HTML + PRD만 첨부하면 충분 — 클로드가 HTML/CSS 직접 읽음 |
| 디자이너에게 줄 때 | 위 + 와이어프레임 PNG 10장 (HTML을 브라우저에서 열고 캡처) |

---

## 1. 한 줄 정의

> **Slate**는 5~20명 사내 개발팀이 쓰는 가벼운 지라 대체 도구. 2주 스프린트 운영, 칸반 보드, 에픽, GitHub/Slack 연동 중심. **Linear의 깔끔함 + Notion의 친근함**이 디자인 방향.

---

## 2. 디자인 톤 & 무드

### 2.1 레퍼런스
- **1순위**: **Linear** (linear.app) — 미니멀, 회색 위주, 적당한 그림자, 빠른 인터랙션 감
- **2순위**: **Notion** — 친근하고 부담 없는 톤
- **피해야 할 것**: Jira (UI 무거움, 시각 정보 과다), Trello (장난스러움 과함), 짙은 색 강조

### 2.2 무드 키워드
- 깔끔 · 조용함 · 절제된 · 빠른 · 한 번에 다 보임
- 색은 **상태/타입 식별 최소한**으로만 — 90% 무채색, 10% 의미 컬러
- 정보 밀도는 **Linear 수준** (Jira보다 조밀, Notion보다 정돈)

### 2.3 디자인 결정의 우선 순위
1. **가독성** > 미적 화려함
2. **속도감** > 풍부한 애니메이션
3. **일관성** > 화면별 개성
4. **단축키 친화** — 모든 주요 액션에 단축키 표시 (`C`, `⌘K`, `↵` 등)

## 5. 레이아웃 시스템

- **그리드 단위**: 4px (모든 여백·간격은 4의 배수)
- **사이드바 폭**: 224px (`w-56`)
- **이슈 상세 우측 메타 패널**: 288px (`w-72`)
- **최대 컨텐츠 폭**: 1200~1280px (보드는 풀폭, 상세 페이지는 1200px)
- **카드 라운드**: 8px (작은 카드), 12px (큰 카드/모달)
- **그림자**: 매우 약하게. `shadow-sm` 수준만. 모달은 `shadow-xl`.

## 6. 컴포넌트 인벤토리

디자인 시스템으로 만들어야 할 컴포넌트:

### 6.1 1단계 (필수)
- `Button` — primary / secondary / ghost / danger
- `Pill` (=Tag/Badge) — 상태·타입·포인트·라벨용. 11개 변형
- `Avatar` — 24/32/40px, 이니셜 폴백
- `IssueCard` — 보드용. 에픽 컬러바 + 키 + 제목 + 메타
- `IssueRow` — 백로그/리스트용. 핸들 + 상태 + 키 + 제목 + 메타
- `Sidebar` — 프로젝트 스위처 + 5개 메뉴
- `TopBar` — 스프린트 셀렉터 + 필터 + 검색 + 빠른 생성
- `Modal` — 빠른 생성, 검색, 확인 다이얼로그
- `Dropdown` — 필터, 상태 변경, 우선순위
- `Input`/`Textarea` — Markdown 입력 포함
- `Comment` — 아바타 + 이름 + 시각 + 본문
- `ActivityRow` — 활동 로그 한 줄
- `EmptyState` — "이슈가 없어요" 등

### 6.2 2단계 (개발 중 추가)
- `VelocityChart`, `BurndownChart`
- `DateRangePicker`
- `MarkdownPreview`
- `MentionPopover`

## 7. 핵심 인터랙션 (애니메이션 가이드)

- **카드 드래그**: 잡으면 살짝 들어올림 (translateY -2px, shadow ↑). 놓는 위치 표시 = 점선 인덱스 선.
- **상태 변경**: 카드 컬러 페이드 (200ms ease)
- **모달 진입**: 페이드 + scale 0.96 → 1 (150ms)
- **사이드바 호버**: 배경 fade (100ms)
- **알림 등장**: 우측 상단 슬라이드 인 + 5초 후 fade out
- **Realtime 카드 추가**: 새 카드 자리에 짧은 highlight (yellow → fade 800ms)

원칙: **200ms 이상은 거의 안 쓰기**. 빠르고 조용한 톤.

## 8. 다크 모드 / 라이트 모드

- **다크 모드 디폴트** 권장 (개발자 도구 컨벤션)
- 라이트 모드도 1단계에서 같이 제공
- 시스템 설정 따라가는 옵션 + 수동 토글 (설정 → 개인 → 테마)

## 9. 반응형

- **데스크탑 우선**: 1280px+
- **태블릿**: 768~1279px — 사이드바 자동 접힘 (햄버거)
- **모바일**: ~767px — 읽기·간단한 상태 변경만. 보드는 single column 스크롤. 백로그는 list 뷰. 1단계 우선순위 낮음.

## 10. 화면별 디자인 포인트

각 화면에서 디자이너가 특히 신경 써야 할 부분.

### 10.1 로그인
- Slate 로고 + 한 줄 카피. 다른 요소 최소화.
- "OAuth 버튼"의 비주얼 무게가 화면의 90%여야 함.

### 10.2 홈 / 프로젝트 스위처
- "내 담당 이슈" 리스트가 핵심 — 매일 첫 접속 시 여길 보고 일 시작.
- 프로젝트 카드는 작게, 리스트는 크게.

### 10.3 보드
- **드래그 인터랙션이 최우선**. 컬럼 간 카드 이동이 가장 자주 일어남.
- 카드 정보는 한 번에 다 보이게 (펼치기 X)
- 컬럼 폭 균등. 컬럼이 비면 빈 상태 일러스트 없이 단순 회색 캔버스만.

### 10.4 백로그
- 위(스프린트)/아래(백로그) 비율 = 보통 1:1 ~ 1:2 (가변)
- 드래그 핸들(`≡`)은 호버 시에만 진하게.
- 인라인 새 이슈 입력이 백로그의 주요 진입점.

### 10.5 이슈 상세
- 본문(좌) / 메타(우) = 7:3 권장 (TDD에 명시한 비율)
- 우측 메타는 **인라인 편집** (필드 클릭 → 즉시 드롭다운)
- GitHub 링크는 본문 아래 별도 박스로 시각적 분리.

### 10.6 에픽 상세
- 진행률 바가 페이지의 시각적 앵커.
- 자식 이슈 리스트는 그루핑(상태별)도 토글로 제공하면 좋음.

### 10.7 스프린트 리포트
- **회고 모드** = 글자 크기 1.5배, 차트 확대, 단축키 없음 (회의실 큰 화면용).
- 벨로시티 막대그래프에 평균선 점선으로 그어주면 좋음.

### 10.8 설정
- 좌측 카테고리 nav가 핵심. 워크스페이스/프로젝트/개인 3그룹 시각적 구분.
- Jira 마이그레이션은 Phase 표시기를 step indicator로 시각화 (현재 어디인지).

### 10.9 빠른 생성 모달 (C)
- 첫 입력에 즉시 포커스.
- 제목만 채우고 `Enter` → 생성. 그 외 필드는 모두 선택사항이라 작게.

### 10.10 글로벌 검색 (⌘K)
- 카테고리 헤더로 결과 그룹핑 (이슈/코멘트/에픽/사용자)
- 키보드 네비 표시는 항상 하단에 (`↑↓` `↵` `Esc`)

```
요구사항:

```

## 12. 디자이너에게 줄 때 (인간)

위 문서들 + 추가로 필요한 것:
- 와이어프레임 PNG 10장 (HTML 파일 브라우저로 열고 직접 캡처)
- 무드보드 (Linear/Notion 스크린샷 몇 장)
- 회사 로고/아이콘 (만약 있다면)
- 기존 사내 디자인 시스템 (만약 있다면)

PNG 빠르게 만드는 법:
- Chrome 확장 "GoFullPage" 설치 → HTML 파일 열고 클릭 한 번 = 전체 페이지 PNG
- 또는 Cmd+P (Print) → PDF 저장 → PDF에서 각 페이지 PNG로 export
